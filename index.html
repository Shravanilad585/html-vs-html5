01 / the story

From a few tags to a full web platform

HTML describes what each part of a page is. HTML 4 did that with generic boxes and relied on plugins for everything else. HTML5 gave the markup real meaning and put media, graphics and apps inside the browser.

  1. 1991First description of HTML by Tim Berners-Lee
  2. 1995HTML 2.0, the first formal standard
  3. 1997HTML 4.0, with style sheets and frames
  4. 1999HTML 4.01, the last version of the old line
  5. 2008First public working draft of HTML5
  6. 2014HTML5 becomes a W3C Recommendation
  7. 2019WHATWG Living Standard becomes the single standard

HTML (4.01 and earlier)

  • Pages built from generic <div> and <table> boxes
  • Plugins (Flash, QuickTime) for video, audio and animation
  • Looks mixed into content with <font> and <center>

HTML5

  • Tags with meaning: <header>, <nav>, <main>, <article>, <footer>
  • Native <video>, <audio>, <canvas> and inline SVG
  • Smarter forms and new browser APIs

02 / features

Feature by feature

Each card compares the old way with the HTML5 way.

Doctype

HTML 4
A long line naming a DTD: <!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01//EN" …>
HTML5
<!DOCTYPE html>

Character set

HTML 4
<meta http-equiv="Content-Type" content="text/html; charset=UTF-8">
HTML5
<meta charset="UTF-8">

Page structure

HTML 4
Generic <div id="header">, <div id="menu">. The meaning is only in the names.
HTML5
<header> <nav> <main> <section> <article> <aside> <footer>

Audio and video

HTML 4
Plugins through <object> or <embed>
HTML5
Native <audio> and <video> with <source> and subtitles via <track>

Graphics

HTML 4
Images only, or a plugin
HTML5
<canvas> for scripted drawing and inline <svg> for vector graphics

Forms

HTML 4
Basic input types. Checking an email or required field needs JavaScript.
HTML5
Types like email, date, range, color, built-in required and pattern, plus <datalist>

Client storage

HTML 4
Cookies only, about 4 KB each
HTML5
localStorage and sessionStorage, several MB per site

Browser APIs

HTML 4
None in the language itself
HTML5
Geolocation, Drag and Drop, Web Workers, WebSockets and the History API

Presentational tags

HTML 4
<font>, <center>, <big>, <strike>, <frameset>
HTML5
Obsolete. Appearance is handled by CSS.

Mobile and responsive

HTML 4
Not designed for phones
HTML5
Viewport meta tag, <picture> and srcset for responsive images

Error handling

HTML 4
Browsers guessed differently when markup was broken
HTML5
A defined parsing algorithm gives the same result in every browser

03 / usage

Where each one is used

Older HTML today

  • Maintaining legacy sites from the 2000s
  • Old intranet or government pages never rewritten
  • HTML emails, which still depend on table layouts for mail app compatibility

HTML5 today

  • Every modern website and web app
  • Mobile-friendly, responsive sites and progressive web apps
  • Video and audio players, games and charts without plugins
  • Pages that need good accessibility and search visibility

When people say "HTML" today they mean HTML5. Old pages still open in modern browsers, but new work should follow HTML5.

04 / good vs bad

The same page, written badly and written well

Both examples contain the same content: a title, a menu, one article, a related-links box and a footer. The code is on the left and its real rendered result is on the right.

Bad HTML

non-semantic, poor structure

code

<html>
<head>
<title>page</title>
</head>
<body bgcolor="#f2f2f2">

<center><font size="6" color="#1b6b5a"><b>My Notes</b></font></center>
<br><br>

<div id="menu">
  <a href="#">Home</a> | <a href="#">Notes</a> | <a href="#">Contact</a>
</div>

<div class="main">
  <div class="title"><b><big>What is HTML?</big></b></div>
  <div class="date">19 October 2026</div>
  <div>HTML is the language used to structure web pages.
  <br><br>
  It tells the browser what each part of a page is.</div>
  <img src="tags.svg" width="160">
  <div class="caption"><i>Page structure</i></div>
  <b><i>Click here</b></i> to read more.
</div>

<div class="side"><b>Related</b><br>
<a href="#">CSS basics</a></div>

<table width="100%"><tr><td align="center">Copyright 2026</td></tr></table>
</body>
</html>

rendered result

  • No doctype, lang or charset, so the browser falls back to quirks mode.
  • <font>, <center>, <big> and bgcolor mix looks into content.
  • The title is a bold <div>, so there is no real heading.
  • Every part is a plain <div>, so nothing marks the menu, article or footer.
  • <br><br> used for spacing and a table used for the footer.
  • The image has no alt text.
  • Wrong nesting: <b><i>…</b></i>.
  • "Click here" tells nobody where the link goes.

Good HTML5

semantic, clean structure

code

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>What is HTML? | My Notes</title>
  <style>
    body { font-family: sans-serif; margin: 0; background: #f2f2f2; }
    header, main, footer { padding: 1rem; }
    header { background: #1b6b5a; color: #fff; }
    header h1 { margin: 0 0 .5rem; }
    nav ul { display: flex; gap: 1rem; list-style: none; margin: 0; padding: 0; }
    nav a { color: #fff; }
    figure { margin: 0; }
    footer { text-align: center; }
  </style>
</head>
<body>
  <header>
    <h1>My Notes</h1>
    <nav aria-label="Main">
      <ul>
        <li><a href="#">Home</a></li>
        <li><a href="#">Notes</a></li>
        <li><a href="#">Contact</a></li>
      </ul>
    </nav>
  </header>

  <main>
    <article>
      <h2>What is HTML?</h2>
      <p>Published <time datetime="2026-10-19">19 October 2026</time></p>
      <p>HTML is the language used to structure web pages.
         It tells the browser what each part of a page is.</p>
      <figure>
        <img src="tags.svg" width="160"
             alt="Layout diagram: header, main article, aside and footer">
        <figcaption>Page structure</figcaption>
      </figure>
      <p><a href="#">Read more about HTML</a></p>
    </article>

    <aside>
      <h2>Related</h2>
      <ul><li><a href="#">CSS basics</a></li></ul>
    </aside>
  </main>

  <footer>
    <p>&copy; 2026 My Notes</p>
  </footer>
</body>
</html>

rendered result

  • Doctype, lang, charset and viewport are all present.
  • Landmarks: <header>, <nav>, <main>, <article>, <aside>, <footer>.
  • One <h1>, then <h2> for sections.
  • The menu is a list of links inside <nav>.
  • <time datetime> gives a machine-readable date.
  • <figure>, <figcaption> and alt describe the image.
  • Descriptive link text and correctly nested tags.
  • All styling lives in CSS.

What a screen reader or search engine understands

Both pages could be styled to look alike. What differs is the meaning each carries.

Bad HTML

  • div #menu
  • div .main
    • div .title (only bold text)
    • div .date (only text)
    • div (paragraph split by br)
    • img (no description)
    • div .caption
  • div .side
  • table (used as a footer)

Good HTML5

  • banner (header)
    • heading 1: My Notes
    • navigation: Home, Notes, Contact
  • main
    • article
      • heading 2: What is HTML?
      • time: 19 October 2026
      • paragraph
      • figure with caption
    • complementary (aside)
  • contentinfo (footer)
AccessibilityScreen reader users can jump to the nav, main content or footer.
SEOSearch engines know the heading, article and date.
MaintenanceClear structure that other developers can read quickly.
ConsistencyA doctype and correct nesting make browsers agree.

06 / cheat sheet

Good HTML at a glance

Do

  • Start with <!DOCTYPE html>, lang and charset
  • Use landmark tags for the page structure
  • Keep heading levels in order
  • Give every image meaningful alt text
  • Close and nest tags correctly
  • Keep styling in CSS

Don't

  • Build everything out of <div>s
  • Use <font>, <center> or bgcolor
  • Fake headings with bold text
  • Use <br> for spacing or tables for layout
  • Write links that say "click here"
  • Leave out the viewport meta tag
